终端在做梦 —— 灵感源自 2026 年 10 月 21 日 Hacker News 热门讨论（simedw 发布，约 621 点赞、186 条评论）：《WorldTUI: I trained a 360M model to pretend to be a terminal》。

核心设定令人震撼：**屏幕背后根本没有 bash，也没有真实的文件系统**。用户的每一个按键（原始字节）都被输入进一个小型语言模型，模型输出的不是传统的文本追加流，而是**整个终端字符网格在按键前后的差分（Screen Diffs）与光标位置**。

### 核心设计与工程技巧

1. **训练数据与场景泛化**：
   - 模型基于 Qwen2.5-Coder-0.5B，在 Docker 真实程序运行中录制的数据上微调。
   - 训练集包含 33.6 万个会话周期（episodes），约 20 亿 tokens。
   - 随机化注入用户名、主机名、提示符、工作目录与角色；加入 1.2% 的打字拼写容错噪声。
   - 35% 的会话从中间状态（如正处于 vim 编辑、贪吃蛇游戏或 tmux 分屏中）切入，迫使模型学会从任意静态屏幕继续预测。
   - 在一块 RTX 4090 上累计训练仅约 75 个 GPU 小时。

2. **屏幕即状态（The Screen is the State）与 COPY 技巧**：
   - 真实终端是一个二维字符矩阵，不是单向打字机。传统 LLM 只能向末尾追加 token，无法优雅表达 `clear`（光标跳回左上角）或 vim 内的移动。
   - 滚动一整屏如果逐行重画，单次按键需消耗约 3,000 个 tokens。
   - 作者引入 `ROW_n COPY m` 语义：将上一帧的第 m 行整行复制到当前帧第 n 行，每行仅消耗 3 个 tokens。
   - 词表缩减至极致的 **333 个 tokens**（256 个单字节 token + 64 个行标记 token + 少量特殊操作标记）。基于语法的受限解码（Grammar-constrained decoding）保证每次预测出来的都是结构合法的屏幕更新。

3. **DAgger 自我修复训练（Self-Repair）**：
   - 交互式生成的最大痛点是“误差累积”：一旦某一步产生错误文件名，后续状态就会全部雪崩。
   - 解决方案：在真实会话中截取一个时间点，让模型预测接下来的 1 至 4 个动作，一旦与真实屏幕有微小差异，立即构造一个纠错样本来修复屏幕。
   - 关键硬性约束：纠错内容**严禁使用模型自主幻觉出的新词汇**，必须严格取自真实历史屏幕或用户当前输入，防止强化幻觉。三轮自我修复将 PresetBench 从 24/47 提升至 38/47（int4）。

4. **并行行生成与投机校验**：
   - 终端多数行互不干扰，因此一个 batch 内并行生成各行，最后一步统一预测光标，将 RTX 4090 上大画面的 p95 延迟从 6.7 秒降至 0.87 秒。
   - 针对行间冲突引入串行验证器：保留并行草稿直到首个分歧 token，随后退回修正。
   - 在 M4 Mac 浏览器的 WebGPU 本地运行中：日常单键响应仅约 60 毫秒，`man test` 这类大屏全刷也仅需约 0.9 秒。

5. **从 494M 极限瘦身至 208MB**：
   - 原版 Qwen2.5-Coder-0.5B 拥有约 4.94 亿参数，其中 151,936 个庞大词表的嵌入层就占了 1.36 亿参数。
   - 剪除无用词表、仅保留 333 个终端 token 后，参数量骤降至 3.6 亿（990 MB 降至 716 MB）。
   - 配合 int4 量化，最终体积压到惊人的 208 MB，通过纯 JavaScript Qwen 解码器与 WebGPU WGSL compute shaders 在浏览器标签页内纯本地跑通。

### 诚实的局限与第 7 层的残酷启示

- **绝非可靠的文件系统**：执行 `echo green >> colors` 之后，紧接着运行 `cat colors`，追加的绿往往不会出现；组合陌生的非常规命令时极易穿帮。
- **蒸馏的教训**：在不重训的情况下仅仅剥离第 7 层（layer 7），模型的下一个 token 预测准确率看起来几乎毫无变化（从 99.3% 微跌至 98.9%），但跨文件精准记忆回读（Memory readbacks）却从 64/64 断崖式崩塌为 0/64 —— **模型表面上看起来依然完好，却在暗中彻底失去了记忆**。
